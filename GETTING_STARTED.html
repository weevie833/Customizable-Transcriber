Prerequisites before starting
  1. You will need a Google Gemini Pro account or an Anthropic Claude Pro account to use the app because it requires a direct data connection using an API key (a password) to access your AI account. A free account includes access to API keys, but the data rates and usage caps of a free account will severely limit your capabilities and will not allow access to Pro AI models, which are required in this app. Also, free accounts use your data to train the company's AI models, which violates the privacy terms of this app.
  2. Once you have purchased a Pro account, go to Gemini's AI Studio or Claude's Platform dashboard to create an API key. An API key is a password that lets the app use your API account to process files. Copy your API key and save it securely on your computer -- do not save it in an email or in an online file. Treat your API key like a private password.
  3. In your API account, set up a billing method to pay for the token usage required to process image files. This is separate, pay-as-you-go billing, unrelated to any consumer subscription's monthly price. Token costs are generally very inexpensive, but they can add up quickly with large batches of files. Check your API account dashboard to monitor your usage so you don't run out of tokens in the middle of a batch. Most billing methods include an automatic replenish option.
How does the app work using AI?

The app uses AI to interpret your images, then transcribes them into digital text according to the rules you set in your prompt. That's why your prompt needs to be very explicit about what's in your files and what the content means. The Prompt Builder is designed to help you build the strongest prompt possible.

The app processes images into digital text the same way as if you uploaded a single image into ChatGPT's, Claude's, or Gemini's chatbot -- except you have more control over how the image is interpreted. The app also lets you process a large batch of files without running into chat-length limitations (chatbots get "dumber" over the course of a long conversation). The prompt profile feature lets you reload and repeat the same process consistently and reliably.

In the footer area, you'll see a Privacy link that explains how data is used in the app, along with other security details.

Preparing your project

This section explains how to prepare your files for processing and how to put together some "ground truth" material for the AI to use as a reference. First, place your image files in a folder that's easy to find so you can select it later. Name each image with a descriptive term and a number, like this:

Chiusa Sclafani Battesimi_001.jpg Chiusa Sclafani Battesimi_002.jpg

The name of each file gets copied into the transcript and the index spreadsheet so you can easily locate the original file for manual review. Avoid names like image_201.jpg -- you may have many other files in your collection with the same generic name. Several file-renaming utilities can do this very quickly; just search "file renamer app for Windows" or "file renamer app for Mac." They're often inexpensive and simple to use. Use the Sequence feature if it's OK to rename your files completely -- choose a three-digit numbering scheme if you have hundreds of files. If you need to keep part of your existing filenames, use the Prepend feature, then use Sequence to add numbers at the end. Pro Tip: Skim through all of your images AFTER you number them and BEFORE you process them to look for duplicates (keep the best copy) and to locate instances where the photographer is displaying an inserted slip of paper in between pages. When this happens, it is likely that the prior image is a duplicate of the "slip of paper" image - you may want to crop out everything except the slip of paper, or remove it completely and transcribe it manually. If you do not skim your images first before you pocess them, your converted index will contain missing or errant entries.

Content prep: The AI system needs examples of your content to use as a reference for predicting what it will find when it transcribes your images into digital text. At the top of the Prompt Builder page, you'll see a "Download DOCX" button that downloads prompt profile worksheets for each type of content. The worksheets include sections where you can enter a manually transcribed example of your source material. Supplying 2-3 examples of accurate entries will help the AI system work more accurately.

How does the Prompt Builder work?

The first time you use the app, you need to create a prompt profile. On the Prompt Builder page, look for "Create a new profile" and follow the instructions for each section. You'll also see a "Download DOCX" button that downloads prompt profile worksheets for each type of content. It's a good idea to work out all the details of your prompt profile in the DOCX before entering content into the Prompt Builder page -- it can take some time to put everything together. You will input:

  • Reference guides for the format of your content.
  • Structural guides that show where key content is located in each entry.
  • Common abbreviations, terms, and other quirks unique to your material.
  • A list of surnames and given names for the region you're transcribing. This is very important -- it gives the AI system a lexicon to compare against the most likely interpretation of the scribe's handwritten script.
  • Editorial rules unique to your content (optional).
  • At least one fully transcribed and corrected example. This is very important for showing the AI system what a typical entry should look like. Add 2-3 examples if you can, using the "Add another example" button.

Once you've assembled all the source material for your prompt in the DOCX worksheet, enter your content into the Prompt Builder. Try the Preflight Test to make sure your prompt is working -- it will also offer suggestions to improve your prompt. These are optional, but highly recommended.

Next, choose whether you want your transcript entries translated from their native language into Italian or English (or both). Note that this uses your AI account for the additional translation step.

Last, name your profile and save it. It will then appear throughout the rest of the app once you refresh the pages. Pro tip: always add a version number to your profile name, like "Chiusa Sclafani Battesimi V1," since you will likely create multiple versions of your profiles over time.

Updating your prompt profile: On the Prompt Builder page, in the top blue section, select your saved profile from the list. It will load all of its settings into the Prompt Builder. Change whatever you need, then scroll to the bottom and either click Update Profile to overwrite the profile you selected, or Save as New Profile to create a new version of it.

How to generate a transcript

On the Transcribe page, select the source folder with your image files. If you're just starting a new project, place only 2-3 files in your source folder to test your prompt before running the entire batch.

Select your AI model and paste in your API key. Keep your API key somewhere secure on your computer -- never post it online or send it in an email. It's the same as a password. The app does not save your API key.

Select your preferred Process order, then select the file type that matches your collection of images.

Select your Prompt profile, then click Preflight Check to confirm your settings are correct. When you're ready, click Confirm and Run. The app processes your files in the order you selected. Watch the Progress Console at the bottom -- you'll get an alert when the batch is complete.

When the batch is complete, click Download Document, and a DOCX transcript will download to wherever your browser is set to save downloads.

Note: Do not edit the header in the DOCX file. That data is used during XLSX conversion to automatically detect what kind of content is in your transcript.

Off-Peak Mode - You can save ~50% on the cost of API calls (the cost of processing each image using AI) by using the Off-Peak Mode when you are ready to run your batch. Leave the app running and your computer turned on so that your batch can run at a discount rate when your selected AI system has lower demand. This is especially useful if you are running a large batch of images. Check the Console for status updates. Note that you can only run one batch at a time, so plan to use Off-Peak Mode if do not have any other batches to run. Check your selected AI system's documentation to calculate your savings.

How to convert your transcript into a spreadsheet

Once your transcript is complete and you've reviewed the DOCX file, you're ready to convert it into an XLSX spreadsheet index.

Go to the XLSX Conversion page, select an AI model, and paste in your API key.

Upload or drag and drop your transcript DOCX file into the upload panel. The app automatically detects the type of content in your transcript, and the Source material menu sets itself to match.

In the "Choose the source material" panel, type in the image range you want converted, or check Process all. Use the image range if you want to skip certain images (because there's nothing in them) or test a range of entries before converting everything. The numbers in the image range refer to the image number at the end of the source image's filename, as copied into the start of each section of your transcript, for example:

START OF RECORD: San Mango D'Aquino Matrimoni_Book 18 Page_004.jpg

The image number for the record above is "004."

In the "Choose output languages" area, you can pick from whatever's available in the transcript. If the transcript has both a native-language version and a translation, you can convert one or both. Note that this step uses AI processing too, so more tasks means more cost.

Click Preflight to check your settings and confirm the AI system can detect the entries in your transcript. Review the results, then click Convert if everything looks right. If Preflight reports an error, you can stop and fix it, or override the error and proceed anyway.

The process takes a few minutes depending on how many entries need processing -- for very long transcripts, conversion can take up to 10 minutes or more.

When conversion is complete, click the download button and it will download an XLSX file to the location set in your browser for saving downloads. XLSX index files follow the indexing templates from the Italian Parish Records organization.

Why can't I generate an index directly from my image files?

It is technically possible to extract image data and directly place data into a spreadhseet index, but there are compelling reason why this is not recommended.

Two tasks, fused into one unauditable step: Going straight from image to index asks a model to do two cognitively distinct things at once: read the page (resolve ambiguous handwriting, archaic letterforms, Latin declension, faded ink, marginal notes versus body text), and reason about schema (decide which of a fixed set of template columns each fact belongs in, apply normalization rules, and discard everything that doesn't fit). When both happen inside one call with no artifact in between, a wrong value in a cell is undiagnosable. There is no way to tell “the model misread the handwriting” from “it read correctly but mapped the value to the wrong field” from “it quietly invented a plausible value to fill a cell it wasn't confident about.” Those are three different failure modes needing three different fixes, and collapsing the pipeline destroys the ability to tell them apart at exactly the scale (hundreds of images, run unattended) where that diagnostic signal matters most, because no one is eyeballing every cell.

Refinement of the app: Every non-obvious editorial rule this application has accumulated was discovered by comparing transcript text against verified ground truth, not by inspecting spreadsheet cells:

  1. A one-letter Latin misread, silently propagated. Confusing filius/filia (“son of”/“daughter of”) regenders a child's given names throughout the output, because fidelity rules normalize name endings to agree with whichever word was read. This was only visible because the transcript preserves the actual Latin word as text that could be read and cross-checked.
  2. A surname-inheritance assumption that would have erased real exceptions. Comparing 349 transcribed rows against a verified index found 8 real, deliberate exceptions to a “child inherits the father's surname” pattern — spelling variants, children carrying the mother's surname, foundlings. A rule copying surnames forward would have silently normalized precisely the records a genealogist would be searching for.
  3. A heading-versus-body disagreement rule. Some entries show the same person's name in two different, both-legitimate written forms in one entry (a genitive form in a marginal heading, an ablative form in the body). This was only caught by reading full transcript text side by side, not by looking at a single resolved index value.

Precedent for staged processing:

  1. Chain-of-thought / scratchpad prompting (Wei et al., 2022). The most directly relevant precedent: language-model accuracy on complex tasks measurably improves when the model produces an intermediate representation before the final structured answer, versus jumping straight to a terse output. A full transcript is that intermediate representation — not overhead, but the mechanism that makes the final extraction more reliable.
  2. ETL staging layers. Standard data-warehousing practice (Kimball-style architecture, dbt's staging models) never transforms raw source directly into a final modeled table — a staging representation is materialized first so each transform can be tested and re-run independently.
  3. Archival science's own distinction between transcription and calendar/index. A transcription is understood as a faithful rendering of a record; an index or calendar is an acknowledged, lossy reduction built for retrieval, not a record of truth. Standard digitization practice (ALTO/METS, Transkribus-style pipelines) keeps the transcribed text as a first-class artifact independent of whatever index is built from it, specifically for audit and re-processing.

The transcript preserves optionality the index cannot: An index schema is a fixed set of columns decided in advance for one anticipated use — name-and-date lookup. A transcript is schema-agnostic: it retains whatever the register actually contains, including structure no index template was designed to capture. This is the same reasoning behind keeping canonical/raw data and deriving narrow views from it, rather than keeping only today's view: a view nobody preserved the substrate for cannot be re-derived later.

Advanced Features

On the Transcribe page, look for the Manual Prompt Override section and expand it to see three fields: Role and local context, Ground truth and reference material, and Output format. You can paste in your own prompt manually, without using the Prompt Builder, and save it as a new custom profile. You can also load an existing prompt profile, edit it by hand, and save it. However, custom profiles can't be loaded back into the Prompt Builder for revision.

All prompt profiles are saved in a separate location on your computer, so they're preserved whenever you update the core software:

macOS: ~/Library/Application Support/Customizable Transcription/ Windows: %APPDATA%\Customizable Transcription\ Linux: ~/.local/share/Customizable Transcription/ (respecting XDG_DATA_HOME if set)

Sharing prompt profiles: at the bottom of the Prompt Builder page, look for the Import/Export Profiles section and expand it. Select a profile to export and click the download button. The profile is a plain text file -- it doesn't execute code -- so you can share it by email. You can import a shared profile using the Import a profile feature.

Test Mode: Test Mode lets you generate multiple transcripts of the same source material using different models so you can compare accuracy against an existing corrected transcript of the same material. You can create multiple batches with different model pairs and run them all automatically.

When processing is complete, use the Compare Results feature to compare your test transcripts against your corrected transcript. The app generates a report calculating the accuracy of each draft against the corrected version, based on a set of metrics -- each metric set includes an explanation of the figures and how they were derived.
